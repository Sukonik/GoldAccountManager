Roadmap

Small first, with every later feature fitting behind an interface.

Phase 0 · Foundations done

  • Go module, CI, linting and a vulnerability scan.
  • packet: the format, safe parsing, revision comparison, canonical-JSON checksums compatible with Payout Lab.
  • verify: keyed subjects, signed attestations, a demo confirmation channel.
  • goldd packet new and goldd packet check.
  • Fuzz testing, which already found two real parser bugs.
  • This documentation site and Blue Bolt UI.
  • A browser packet reader in JavaScript and the Try it demo. Both readers run the same shared test cases, so they agree on what a valid packet is.
  • Release automation: one command publishes a site version, keeps a preserved copy and regenerates the README tables.

Phase 1 · Confirmation in progress

Built:

  • The confirmation server for email links: click-to-confirm page, one-time pickup of the signed attestation, per-address and per-client rate limits, bounded state, strict requests, no secrets in logs.
  • Per-app free-tier quotas (maxSubjects) with block or waitlist, and CORS for browser apps.
  • goldd serve (with a zero-setup -dev demo) and goldd keygen. Keys live in the environment, not in config.
  • An SMTP mailer that needs TLS unless the server is local.

Still to do in this phase:

  • A durable store (so a restart keeps quotas and waitlists) and a rate limiter shared across instances.
  • Google sign-in and the email-reply channel.
  • Connecting the Try it page to a server, so a visitor can confirm an email end to end.
  • A recovery flow for a lost packet.

Phase 2 and later

  • Encrypted packets with a passkey-derived key. This must land before any private data uses packets.
  • Passkeys (WebAuthn), Telegram and WhatsApp channels, and a paid SMS channel behind hard caps.
  • A hosted tier for apps that need server-side data.
  • Signed offline grants for desktop software.
  • Per-app plans, free-tier user limits and billing.

Deliberately not included

  • One account shared across apps. Each app is isolated by design.
  • Acting as a sign-in provider for outside developers.
  • A full SAML and enterprise single sign-on stack. Use a project like Keycloak for that.

The longer planning notes are in the repository: SCOPE.md, FEATURES.md, PLAN.md and RESEARCH.md.
