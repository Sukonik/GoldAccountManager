Early development · Phase 0

Your account is a file you own.

GoldAccountManager is an open-source Go toolkit for user accounts that start with no server, no sign-up and no cost, and add confirmation by email, phone or Google only when an app really needs it.

How packets work View on GitHub

Three tiers, chosen per app

Each app decides how much server it needs. Every app is its own isolated account space: the same person using two apps has two unrelated accounts, and nothing links them.

Tier 0 · Packet only

$0 to run

The account is a plain JSON file the user keeps. No sign-up, no database, no server. Good for utilities and tools.

Tier 1 · Verified packet

Tiny service

The user confirms an email or phone once. A server signs a short attestation that travels inside the packet. No re-confirmation needed.

Tier 2 · Hosted account

Planned

For apps whose server must hold the data, such as matching and messaging. The packet becomes export, backup and portability.

Why a file?

  • Never locked out. A ban, an outage or an expired session cannot take away a file the user holds.
  • Free to start. Tier 0 has no users to count and nothing to host.
  • Fewer paid messages. SMS costs money everywhere. The best way to save is to send fewer codes.
  • Private by design. Attestations carry a keyed hash, never the email address or phone number, and differ for each app.
  • Offline friendly. A signed packet can be the offline grant for desktop software.

Try it

Needs Go 1.24 or newer.

git clone https://github.com/Sukonik/GoldAccountManager
cd GoldAccountManager
go run ./cmd/goldd packet new -app notes-demo -name "Sam's notes" -o sam.gold
go run ./cmd/goldd packet check -app notes-demo sam.gold
Honest status

This is Phase 0: the packet format, the attestation code and a small command line. There is no server, no web sign-in and no hosted tier yet. See the roadmap.

The idea comes from Payout Lab, a no-sign-up dividend tracker whose portfolio is a file. The interface is Blue Bolt UI.
