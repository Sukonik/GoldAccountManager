Verification

Confirm an email or phone number for free when possible, and pay for an SMS only as a last resort.

There is no free outbound SMS

Carriers and providers charge for every code you send. So the approach is not a free-SMS trick. It is to avoid sending wherever possible. Carrier email-to-text gateways such as number@txt.att.net are reported shut down or unreliable, so we do not build on them.

The ladder, cheapest first

An app offers whichever rungs the user already has, and can hide any rung. Free plans hide the paid SMS rung by default.

Confirm once, attest forever

After any rung succeeds, the server signs a short attestation bound to one app and one packet. The packet carries it. Nothing needs to be sent again until the user recovers an account. Three properties matter:

  • No address or number inside. The attestation's subject is an HMAC of the normalized email or phone under an app-specific secret. The same person in two apps gets two unrelated subjects. (Someone holding every key could still link them, so the privacy promise depends on trusting the operator.)
  • Cannot be moved. The signature covers the app id and the packet id. An attestation copied onto another packet or into another app reports bad-signature.
  • The method is signed. An app can require a passkey for one action and accept an email link for another, and a user cannot upgrade a claimed method by editing the file.

In Go

// Server side: keep the signing key and the app secret private.
signer, _ := verify.NewSigner("k1", privateKey)

email, _ := verify.Normalize(packet.KindEmail, "Sam@Example.com")
subject, _ := verify.Subject(appSecret, p.AppID, packet.KindEmail, email)
att, _ := signer.Attest(
    p.AppID, p.PacketID,
    packet.KindEmail, packet.MethodEmailReply,
    subject, now, now.AddDate(1, 0, 0),
)
p.Attestations = append(p.Attestations, att)

// Later, any app with the public key can check it.
checker := verify.NewChecker(map[string]ed25519.PublicKey{"k1": signer.PublicKey()})
results := checker.Check(p, time.Now())
if verify.Has(results, packet.KindEmail) {
    // a valid, unexpired email confirmation
}

Channels

Anything that can prove control of an email or phone implements the small verify.Channel interface. Phase 0 ships CodeChannel, a demo channel that prints a six-digit code instead of sending one. Codes expire after 10 minutes, allow five tries and work once. Real channels (magic link, reply email, Telegram, SMS) come in later phases.

Rules that keep it cheap and safe

  1. Passkeys after the first confirmation, so later sign-ins send no codes.
  2. The app chooses which rungs to show.
  3. No single method is a lock: a user can add a second one later.
  4. Rate limits on everything: per number, address, IP and app.
