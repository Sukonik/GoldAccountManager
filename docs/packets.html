Packets

A packet is one plain JSON file that is the user's account for one app. It holds the app's data, an identity, a revision history and any server-signed attestations.

The envelope

FieldMeaning
format, schemaVersion"gold-packet" and 1. A file with a higher version is rejected whole, never half-read.
appIdWhich app this account belongs to. Apps pass their own id when opening, so a packet for one app does not open in another. This is what keeps accounts isolated.
packetIdpk_ plus 13 random characters (65 bits). A label, not a password and not proof of anything.
revisionId, parentRevisionId, lineageEvery save makes a new revision that remembers its parent. The lineage (the last 200 revisions) tells two copies apart as identical, newer, older or diverged.
payloadThe app's own data: a JSON object, at most 4 MiB and 32 levels deep. The app supplies a validator that rebuilds it from known fields.
attestationsUp to 8 server-signed statements that this packet is bound to a confirmed email, phone or device. See Verification.
originPresent when a file was opened as a separate copy, and records where it came from.
checksumSHA-256 of the canonical JSON of everything else.

Checksum is not a signature

Read this before relying on a packet

The checksum catches accidental damage. Anyone can edit a file and recompute it. A parser warns when it does not match, but it does not prove who wrote the file. Anything a server must trust (a verified phone, a paid plan, an admin role) has to be a signed attestation, checked against the server's public key.

Opening a packet safely

A packet is untrusted input, so parsing never executes anything and follows fixed rules:

  1. Files over 5 MiB are refused. A leading byte-order mark is ignored.
  2. The format and version are checked before anything else.
  3. The envelope is rebuilt from known fields only. Unknown fields are dropped.
  4. Field names are case-sensitive. Go's JSON decoder matches AppId to appId, but other readers do not, and two readers disagreeing about one file is how smuggling attacks work. Fuzzing found this, and now such files are rejected.
  5. Ids, dates, names and attestations are checked against fixed patterns and limits.
  6. The payload must be an object within the size and depth limits, then goes through the app's validator.

Comparing two copies

When the same packet shows up twice, for example from a phone and a laptop, packet.Compare reads the revision history. There is no silent "last write wins". If both changed, the result is diverged and the app should offer a separate copy.

RelationMeaningWhat an app should offer
identicalSame revisionNothing to do
incoming-newerYour revision is in its historyContinue from it, or open a copy
incoming-olderIts revision is in your historyOpen a copy, or replace yours after a backup
divergedBoth changedOpen a copy (recommended)
different-packetDifferent packetIdOpen it as another account

In Go

now := time.Now()
p, _ := packet.New("notes-demo", "Sam's notes", packet.AppInfo{Name: "Notes Demo", Version: "0.1.0"}, now)
p.Payload = json.RawMessage(`{"theme":"dark"}`)
file, _ := p.Marshal() // write this to disk: it is the user's account

opened, warnings, err := packet.Parse(file, packet.ParseOptions{
    ExpectAppID: "notes-demo", // keeps accounts isolated per app
    ValidatePayload: func(raw json.RawMessage) (json.RawMessage, error) {
        // rebuild the payload from whitelisted fields, or reject it
        return raw, nil
    },
})

The full API, with runnable examples, is in the package documentation: go doc ./packet. The same rules are written out in docs/packet-format.md.

In the browser

A second reader written in JavaScript, assets/gold-packet.js, follows the same rules and runs the same shared test cases as the Go code (packet/testdata/parity.json). Those cases were checked by deliberately breaking each reader to make sure a test notices. You can use it on the Try it page: make a packet, download it, and open it again. It does not verify attestation signatures.

Limits to know about

  • Not encrypted yet. A packet is plain JSON. Encryption with a passkey-derived key is planned and must land before any private data uses packets.
  • A lost file is a lost account unless the user also confirmed an email or phone, or kept a backup.
  • Sync between devices is manual in Tier 0.
  • A file cannot enforce quotas, roles or paid plans. Only signed attestations can.
